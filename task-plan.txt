Nethra Data Explorer - Sprint And Task Plan
============================================

Product Goal
------------
Build an agentic data-exploration app where users can import a dataset, define or confirm metadata, discover the dataset's ontology and semantic structure, and the app dynamically generates filters, charts, summary cards, data quality checks, trend analysis, natural-language explanations, suggested insights, and reports.

The first use case is poverty tracking, but the system should later support health, education, climate, economy, and other data domains without creating one custom page per dataset.


Recommended Stack
-----------------
- Frontend: React + TypeScript
- Charts: Recharts or Apache ECharts
- Data import: CSV/JSON upload
- Initial data: mock poverty datasets
- Agent layer: rule-based analysis first, OpenAI integration later
- Storage: local browser storage first, database later
- Testing: unit tests, UI tests, and manual demo checklists
- Delivery workflow: Codex implementation workspace, GitHub commits, pull requests, review notes
- Sprint tracking: Jira MCP if available, otherwise markdown progress tracker files


Core Principle
--------------
Dataset schema and metadata drive the whole app.

When the dataset changes, the UI, filters, charts, insights, and agent behavior should regenerate automatically.

The app should go beyond traditional data discovery by explaining the semantic meaning of the dataset:
- What entities exist in the data
- What indicators or measures are tracked
- Which dimensions describe those indicators
- How columns relate to each other
- What patterns, shifts, anomalies, and segment differences exist
- Which statistical tests or models are appropriate
- What predictions can be made with uncertainty
- Why certain filters, charts, and insights were generated
- What assumptions the app made while interpreting the dataset
- How the agent arrived at an explanation

Pattern Types
-------------
- Trend pattern: steady increase, steady decrease, flat trend
- Change-point pattern: sudden shift or breakpoint
- Outlier pattern: unusual spike, drop, or extreme value
- Gap pattern: persistent difference between groups
- Convergence pattern: groups becoming more similar
- Divergence pattern: groups becoming more different
- Ranking pattern: country or region moves up/down ranking
- Volatility pattern: unstable values over time
- Data quality pattern: missingness, gaps, duplicates, suspicious values
- Relationship pattern: one measure appears related to another measure

Pattern Card Format
-------------------
- Pattern title
- Plain-English explanation
- Why it matters
- Evidence values
- Affected countries or segments
- Time range
- Confidence score
- Importance score
- Data caveats
- Recommended next chart or question

Explainable AI Requirements
---------------------------
- Every pattern must include evidence
- Every explanation must cite the computed facts used
- Confidence must be separated from importance
- Missing data must reduce confidence
- Agent should distinguish observation from interpretation
- User should be able to inspect why the pattern was detected

Agentic Questions

- Why is this pattern important?
- What evidence supports this pattern?
- Could this pattern be caused by missing data?
- Which groups show the biggest gap?

- What changed after 2020?

Sprint 4.6: Statistical Modeling And Prediction Engine
======================================================

Goal
----
Add a basic statistical modeling layer that can test hypotheses, compare groups, analyze time series, and make simple predictions with clear assumptions and uncertainty.

Features
--------
- Statistical method recommender
- Hypothesis testing workflow
- ANOVA workflow
- Time-series analysis workflow
- Basic prediction workflow
- Model result cards
- Statistical explanation panel
- Assumptions and limitations panel

Supported Statistical Capabilities
----------------------------------
- Descriptive statistics: mean, median, min, max, standard deviation, variance
- Group comparison: compare poverty rate across countries, regions, gender, or urban/rural groups
- Hypothesis testing: t-test, chi-square test where appropriate, non-parametric fallback later
- ANOVA: compare numeric measures across multiple groups
- Correlation: Pearson and Spearman where appropriate
- Time-series decomposition: trend, seasonality where data granularity supports it
- Time-series forecasting: simple moving average, exponential smoothing, and linear trend baseline
- Regression baseline: simple linear regression and multiple regression later
- Prediction intervals or confidence intervals where feasible

Method Recommendation Rules
---------------------------
- One numeric measure by category: recommend group comparison or ANOVA
- Two numeric measures: recommend correlation or regression
- Numeric measure over time: recommend time-series trend analysis
- Multiple groups over time: recommend trend comparison and interaction-style explanation
- Categorical outcome by category: recommend chi-square test
- Small or missing-heavy data: warn that statistical results may be weak

Model Result Card Format
------------------------
- Question tested
- Recommended method
- Model or test used
- Result summary
- Test statistic where applicable
- p-value where applicable
- Effect size where applicable
- Confidence interval where applicable
- Prediction interval where applicable
- Assumptions checked
- Data caveats
- Plain-English interpretation
- "What this does not prove" note

Explainable Statistical AI Requirements
---------------------------------------
- Explain why a statistical method was selected
- Explain assumptions in simple language
- Separate statistical significance from practical importance
- Avoid causal claims unless study design supports causality
- Show uncertainty for predictions
- Warn when sample size, missing data, or data quality weakens the result
- Keep calculations reproducible and inspectable

Agentic Questions
-----------------
- Which statistical test should I use?
- Is poverty significantly different between rural and urban areas?
- Are poverty rates different across regions?
- Is the poverty trend statistically increasing or decreasing?
- Are two indicators correlated?
- Predict poverty rate for the next three years.
- How confident is this prediction?
- What assumptions does this model make?
- What does the p-value mean here?
- Is this result practically important?

Tasks
-----
- Define StatisticalModelResult TypeScript model
- Define HypothesisTestResult model
- Define ForecastResult model
- Implement descriptive statistics utilities
- Implement method recommendation rules
- Implement ANOVA baseline
- Implement t-test baseline
- Implement chi-square baseline where appropriate
- Implement correlation analysis
- Implement simple linear regression baseline
- Implement simple time-series forecasting baseline
- Build statistical model cards UI
- Build assumptions and limitations UI
- Connect statistical results to agent context
- Add explainable statistical response rules

Testing Plan
------------
- Descriptive statistics match known fixtures
- ANOVA returns expected result for known grouped data
- t-test returns expected result for known two-group data
- Correlation returns expected sign and strength
- Forecasting returns reproducible baseline results
- Small sample warning appears when needed
- Missing data warning appears when needed
- Agent explanation includes assumptions and caveats

Demo At End
-----------
The user can ask:

The app recommends a statistical method, runs the test, shows the result, explains assumptions, and warns about limitations.

First Build Recommendation
==========================
Start with Sprint -1 and Sprint 0 together. Sprint -1 creates the implementation infrastructure, while Sprint 0 creates the AI-DLC intent and operating model.

After that, start Sprint 0.5 and Sprint 1 together for implementation momentum. Sprint 0.5 creates the app foundation, while Sprint 1 adds dataset import and schema detection.

The first demonstratable version should let us:
- Confirm product intent
- Review functional and non-functional intents
- Load a poverty dataset
- Preview the data
- Detect schema
- Detect ontology and semantic tags
- Discover important patterns with evidence
- Confirm metadata
- Show the generated structure

That gives us the foundation for everything else.
